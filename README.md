# ULUME — Voice-First Agri-Commerce Platform

ULUME connects small/marginal farmers in Karnataka with local agri sellers through a
voice-first, Kannada-language marketplace. Cash on Delivery only, optimised for 2G phones.

This repo contains three apps:

- **Mobile app** (`/`) — React Native + Expo (managed workflow), Android target
- **Cloud Functions** (`/functions`) — Node.js 18 backend on Firebase
- **Admin panel** (`/admin`) — React + Vite + Tailwind

## Prerequisites

- Node.js 18+
- A Firebase project with **Firestore**, **Authentication (Phone provider)**,
  **Storage**, **Cloud Messaging**, and **Cloud Functions** enabled
- Google Cloud APIs enabled on the same GCP project: **Speech-to-Text**, **Text-to-Speech**,
  **Translation**, **Maps Platform**
- A **Meta WhatsApp Business API** account (phone number ID + access token)
- [Expo CLI](https://docs.expo.dev/get-started/installation/) / [EAS CLI](https://docs.expo.dev/eas/) for builds

## 1. Mobile app setup

```bash
npm install
cp .env.example .env   # fill in the keys below
```

Required values in `.env` (all `EXPO_PUBLIC_*` vars are safe to ship in the client bundle):

| Variable | Where to get it |
|---|---|
| `EXPO_PUBLIC_FIREBASE_API_KEY` / `_PROJECT_ID` / `_APP_ID` | Firebase Console → Project settings → General |
| `EXPO_PUBLIC_GOOGLE_SPEECH_KEY` | GCP Console → APIs & Services → Credentials (Speech-to-Text API key) |
| `EXPO_PUBLIC_GOOGLE_TTS_KEY` | GCP Console → Credentials (Text-to-Speech API key) |
| `EXPO_PUBLIC_GOOGLE_MAPS_KEY` | GCP Console → Credentials (Maps Platform key) |
| `EXPO_PUBLIC_GOOGLE_TRANSLATE_KEY` | GCP Console → Credentials (Translation API key) |
| `EXPO_PUBLIC_WHATSAPP_PHONE_ID` | Meta for Developers → WhatsApp → API Setup |

Also place your Android Firebase config at the project root as `google-services.json`
(Firebase Console → Project settings → Your apps → Android app).

Two binary assets aren't generated by this build and need to be added manually — see
`assets/README.md` for the full list (app icon, splash image, Noto Sans Kannada font files).

```bash
npm start          # Expo dev server
npm run android     # run on a connected device/emulator
```

## 2. Cloud Functions setup

```bash
cd functions
npm install
```

Set the WhatsApp secret (never put this in a client `.env`):

```bash
firebase functions:config:set whatsapp.phone_id="YOUR_PHONE_ID" whatsapp.access_token="YOUR_ACCESS_TOKEN"
```

Deploy Firestore rules/indexes and functions:

```bash
firebase deploy --only firestore:rules,firestore:indexes,functions
```

Test locally with the emulator suite: `npm run serve` (from `/functions`).

## 3. Seed test data

Download a service account key (Firebase Console → Project settings → Service accounts →
Generate new private key), save it as `scripts/serviceAccountKey.json` (gitignored), then:

```bash
npm run seed
```

This creates 3 test sellers and 10 test products around Mysuru with geohashes, so the
app has data to render immediately.

## 4. Admin panel setup

```bash
cd admin
npm install
cp .env.example .env   # fill in Firebase web config (Project settings → General → Web app)
npm run dev
```

Admin panel auth is Firebase email/password, separate from the farmer/seller phone-OTP
flow used by the mobile app. To grant an account admin (elevated Firestore) access:

1. Create the user in Firebase Console → Authentication → Add user (email/password).
2. Create a Firestore document at `admins/{that user's UID}` (any field, e.g. `{ role: "admin" }`).

Firestore security rules (`firestore.rules`) check for that `admins/{uid}` document before
granting cross-account read/write access — without it, an admin-panel login only has the
same permissions as a regular signed-in user.

## 5. Building the Android APK

```bash
eas login
eas build:configure
eas build --platform android --profile production
```

`eas.json` is configured to pull the `EXPO_PUBLIC_*` secrets from EAS secrets (`eas secret:create`)
for production builds — set each one before building:

```bash
eas secret:create --name ulume_firebase_api_key --value "..."
# ...repeat for the other keys listed in eas.json
```

The production profile builds an Android App Bundle; the `preview` profile builds a
directly-installable APK for QA.

## Project structure

```
src/            Mobile app source (screens, components, navigation, stores, services, utils, theme)
functions/      Firebase Cloud Functions (order lifecycle, weekly settlement, WhatsApp)
admin/          React + Vite + Tailwind admin panel
scripts/        Firestore seed script
firestore.rules / firestore.indexes.json / firebase.json   Firebase project config
eas.json        EAS Build profiles
```

See inline comments in `firestore.rules` and `functions/` for how the data model and
security rules map to the Firestore schema (users, sellers, products, orders, settlements).

## Notes on Phase 1 scope

- **Cash on Delivery only** — no UPI flow is implemented; the Checkout screen shows UPI
  as a disabled "coming soon" option per spec.
- **First order is always free delivery**, enforced both client-side (`calculateDeliveryCharge`)
  and re-asserted server-side in `functions/orderHandler.js#onOrderCreated`.
- Seller commission (5–8%, defaults to 6.5%) is deducted and settled weekly every Monday
  09:00 IST via the `weeklySettlement` scheduled function.
